# robots.txt served ONLY on usehana.com / www.usehana.com
# (middleware.ts rewrites /robots.txt to this file when the Host is usehana.com)
#
# It must be middleware, not a vercel.json rewrite: Vercel serves an existing static
# file from the filesystem BEFORE evaluating rewrites, and public/robots.txt exists,
# so a rewrite never fires for this path. Middleware runs ahead of the filesystem.
# The vercel.json version was deployed on 13 Sep 2026 and silently served the wrong
# file until production verification caught it.
#
# WHY THIS FILE EXISTS
# usehana.com is the former brand domain. It must stay reachable: its Google
# Workspace mail runs on this domain, and links to usehana.com pages are already
# sitting in sent email, agreements and patient-facing notices. So it is NOT
# redirected — it serves the same deployment as hana.health.
#
# That creates one problem. Every page here already carries
# <link rel="canonical" href="https://www.hana.health/...">, which Google and
# Bing honour, so classic search consolidates correctly on hana.health.
# AI answer engines do NOT honour canonical tags. They were fetching this host
# and citing usehana.com URLs in answers, splitting the brand across two
# domains and sending readers to the old name.
#
# So: traditional search crawlers stay ALLOWED here (they need to fetch the page
# to read the canonical and consolidate). AI crawlers are disallowed here and
# get the identical content from hana.health, where they are fully allowed.
#
# Deliberately NOT used: X-Robots-Tag: noindex on this host. Google advises
# against combining noindex with a rel=canonical pointing elsewhere, because the
# noindex can be attributed to the canonical target. Canonical alone is correct.
